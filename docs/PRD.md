# easy-kanban 产品需求文档（PRD）

> 版本：v0.1（草稿）· 日期：2026-11-23 · 配套：[PAGES.md](PAGES.md)、[DATA-API.md](DATA-API.md)

---

## 1. 背景与问题

小型开发团队的管理者通常同时推进 N 个项目、带着 M 名成员，任务分配关系本质上是一个 **M×N 矩阵**：一个人同时参与多个项目，一个项目同时有多人参与。

现实中这份矩阵散落在聊天记录、口头交代和记忆里。于是出现两个高频、昂贵的时刻：

- 上级突击询问：「A 这个项目现在怎么样了，谁在干？」——管理者答不上来。
- 上级随口一问：「B 和 C 这周在干什么？」——管理者需要临时回忆、翻聊天记录。

现有看板工具以「状态列 + 卡片」组织信息，回答的是「有哪些事要干」，而不是「谁在给哪个项目干活」。它们没有人员维度与项目维度之间的切换能力，矩阵的交叉关系被埋在筛选器后面。

## 2. 产品定位

**给单个管理者使用的「人 × 项目」任务分配矩阵。**

三条设计原则，优先级从高到低：

1. **查询优先**：任何一次「谁在干什么」的查询，都应该在 3 秒内、一屏之内得到答案。呈现信息的质量优先于录入流程的完备性。
2. **录入极短**：新建一条任务从点开到保存不超过 10 秒。录入成本高的工具，管理者不会坚持用。
3. **空格是信息**：矩阵里没有任务的格子同样在说话——某人整行为空意味着闲置，某项目整列为空意味着无人跟进。

## 3. 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 打开页面后 3 秒内能回答任一「项目→人」或「人→项目」问题 | 手工计时，点击 ≤ 3 次 |
| G2 | 一屏内看清人员闲置与项目无人跟进 | 空行／空列有明确视觉标识 |
| G3 | 新建任务 ≤ 10 秒 | 从点击格子到保存完成 |
| G4 | 行列切换一键完成且不打断当前上下文 | 转置后滚动位置与筛选条件保持 |

## 4. 非目标（明确不做）

- 多人协作、多账号、权限角色、评论、@提醒
- 通知、推送、日历同步、邮件
- AI 辅助、健康度评分、进度百分比自动推算
- 甘特图、工时统计、燃尽图
- 状态列看板视图（本产品只有矩阵视图）
- 一条任务多人共担（需要时拆成多条独立任务）
- 数据导入导出、外部系统对接
- 备注支持 Markdown（纯文本即可）

## 5. 用户与典型场景

**唯一角色：管理者（U1）**。系统只有一个账号，成员信息只是矩阵的行标签，成员不登录。

| 场景 | 描述 | 验收标准 |
|---|---|---|
| S1 上级突击询问项目 | 领导问「支付重构怎么样了」，管理者打开页面，直接看该项目这一列：有谁、各条任务的状态与日期 | 从打开到说出答案 ≤ 30 秒，点击 ≤ 3 次 |
| S2 上级询问某几个人 | 领导问「张三和李四这周在干啥」，管理者在这两人的行上从左往右扫一遍 | 一屏内看到这两人跨全部项目的本周任务 |
| S3 周一排期 | 按「本周」筛选，检查谁空着、哪个项目没人，直接在空格子里建任务 | 闲置与无人项目一眼可见 |
| S4 临时派活 | 开会时接到新活，不切页面直接在某格子里建任务 | 建任务 ≤ 10 秒，不必填多余字段 |
| S5 手机上查看 | 不在电脑前，用手机浏览器打开看某人这周在忙什么 | 375px 宽度下可读、可横向滚动，不出现页面级横向溢出 |
| S6 开会记活 | 会上接到一件事，还没想好给谁，先记下来，回头再指派 | 3 秒内记下任务标题，不强制填人员 |

## 6. 核心概念与数据模型（概要）

**术语：归档。** 不删除数据，只是把人员或项目从矩阵中收起来。归档后其历史任务仍保留、仍可被查询，随时可恢复。适用场景：项目结束或暂停、人员离组。归档 ≠ 删除，不丢数据。

**术语：待分配。** 系统内置的一名人员，ID 固定、不可改名、不可归档、不可删除，常驻矩阵第一行（转置后为第一列）。未指派的任务就挂在它名下。把它拖到其他行即完成指派，拖回来即取消指派。

| 实体 | 关键字段 | 说明 |
|---|---|---|
| 人员 Person | id、姓名、颜色、sort_order、archived_at、is_system | 姓名唯一；颜色取自固定 8 色色板；`is_system` 标记内置的「待分配」 |
| 项目 Project | id、名称、颜色、描述、sort_order、archived_at | 名称唯一；归档后不出现在矩阵 |
| 任务 Task | id、标题、person_id、project_id、开始日、截止日、状态、备注、创建时间 | 人与项目均必填，待分配任务挂在系统人员名下；日期可空，精确到天 |
| 账号 Account | id、用户名、password_hash、创建时间 | 仅一行，无角色字段 |

关系约束：

- 一条任务必须属于一个项目和一个人员；挂在系统人员「待分配」名下即表示未指派。
- 矩阵的每个格子 = `(person_id, project_id)` 下所有任务的集合，「待分配」行同样适用。
- 系统人员固定占据第一位，不参与排序，不出现在人员管理列表中，任何删除／归档／改名的请求都会被拒绝。
- 人员与项目的显示顺序由 `sort_order` 决定，可手动拖拽调整。
- 账号是访问凭证，与人员表**互相独立**，不做绑定。

**状态四态**：未开始（灰）、进行中（蓝）、阻塞（红）、已完成（绿）。不设「已取消」，作废即删除。

## 7. 功能需求

### FR-1 人员管理

- 展示：姓名、颜色、进行中任务数；列表不包含内置的「待分配」。
- 支持新建、编辑、归档、恢复。
- 校验：姓名非空、去空格后唯一；颜色必须来自色板。
- 新建人员排在该组末尾（`sort_order` 递增）。
- 归档限制：存在未完成任务时不允许归档，提示「请先转移或完成其 N 条任务」。
- 删除限制：只要名下还有任何任务（含已完成）就不允许删除，提示改用归档。
- 验收：新建 10 秒内完成；重名被拦截；带未完成任务的人员归档被拦截；带任务的人员删除被拦截。

### FR-2 项目管理

- 展示：名称、颜色、进行中任务数。
- 支持新建、编辑、归档、恢复。
- 校验：名称非空且唯一。
- 删除：仅当项目下没有任何任务时允许，需输入项目名称二次确认；有任务时拒绝，建议归档。
- 归档限制同 FR-1。
- 验收：删除需二次确认；有任务的项目删除被拦截；归档后矩阵列消失，恢复后任务原样回来。

### FR-3 任务创建与编辑

- 必填：标题、项目。
- 选填：人员（留空即挂到系统人员「待分配」）、开始日、截止日、备注（纯文本，≤ 500 字）。
- 校验：开始日、截止日各自可为空；两者都填时开始日不得晚于截止日。
- 从矩阵格子内新建时，人员、项目自动带入，日期默认取当前筛选范围，只需填标题。
- 编辑弹窗可修改全部字段；删除需确认。
- 验收：从空格子点「+」到保存 ≤ 10 秒；非法日期被拦截；保存后无需刷新即出现在格子中；人员留空时出现在「待分配」行。

### FR-4 矩阵视图

- 行 = 人员，列 = 项目；两侧为空时展示引导型空状态，不渲染空矩阵。
- 第一行固定为系统人员「待分配」，样式弱化并带锁标识；无未指派任务时压缩为窄行，始终可作拖放目标。
- 一格内最多显示 3 条（PC）／1 条（H5），超出显示「+N」，点击进入格子弹窗。
- 单条任务展示：状态色点 + 标题（单行省略）+ 日期区间（MM/DD–MM/DD）；无日期时显示「—」。
- 点格子空白处打开格子弹窗：该人员在该项目下的全部任务 + 新建入口。
- 行头与列头固定：纵向滚动时表头不动，横向滚动时人员列不动。
- 验收：10 人 × 8 项目下首屏渲染 ≤ 500ms；「+N」计数与实际条数一致。

矩阵示意：

```
                │ 支付重构        │ 数据看板        │ 移动端适配
────────────────┼─────────────────┼─────────────────┼────────────────
 张三           │ ● 接口拆分      │ —               │ ● 首页改版
                │   11/20–11/26   │                 │   11/22–11/28
────────────────┼─────────────────┼─────────────────┼────────────────
 李四           │ —               │ ● 指标口径对齐  │ —
                │                 │   11/24–11/25   │
────────────────┼─────────────────┼─────────────────┼────────────────
 王五           │ —               │ —               │ —      ← 空行标记
```

### FR-5 行列转置

- 一个按钮在「人×项目」与「项目×人」之间切换。
- 转置后：滚动位置、筛选条件、当前打开的弹窗对象保持一致。
- 转置只改变呈现，不改动任何数据。
- 验收：连续点击 10 次无状态错乱；转置后正在查看的对象仍在视口中。

### FR-6 行／列手动排序

- 拖动行头或列头，可调整人员或项目的显示顺序。
- 释放即保存新的 `sort_order`，无需额外确认。
- 顺序对转置后的同名维度同样生效：人员顺序与项目顺序各自独立存储。
- 新建条目追加到末尾。
- 验收：拖动后刷新页面顺序保持；调人员顺序不影响项目顺序。

### FR-7 日期范围筛选

- 预设：本周、下周、全部；自定义：起止日期选择器。
- 默认「本周」，周起始为周一。
- **语义：区间有交集即显示**——`task.start ≤ range.end 且 task.end ≥ range.start`，不是「完全包含」。
- 筛选只作用于**同时具备**开始日与截止日的任务；日期不全的任务不受筛选影响，始终显示（它们没有可归属的周次，藏起来就等于忘了）。
- 筛选结果为空时矩阵框架照常渲染（行头、列头、空行／空列标记都在），顶部以提示条提供「查看全部」快捷入口。
- 验收：跨周任务在相邻两周筛选下均可见；无日期的任务在任意筛选下都可见；空结果不出现纯白页面。

### FR-8 拖拽改归属

- 把任务卡片从 A 格拖到 B 格：按行列方向修改其 `person_id` 和／或 `project_id`。
- 拖拽成功后 toast 提示，5 秒内可撤销。
- 拖拽不改变日期，不改变状态。
- 拖入空行／空列同样有效。
- 拖到「待分配」行即取消指派。
- PC 用拖拽；H5 不提供拖拽，改归属在任务弹窗里用「人员／项目」下拉完成。
- 验收：拖拽后刷新结果保持；撤销可完整恢复。

### FR-9 状态切换

- 点击状态色点循环切换：未开始 → 进行中 → 阻塞 → 已完成 → 未开始。
- 已完成任务在格子内置底并加删除线。
- 状态变更即写库，无保存按钮。
- 验收：点击 4 次回到初始状态；快速连点不产生错序。

### FR-10 待分配行（系统人员）

- 「待分配」是系统内置人员：ID、名称、颜色固定，不可改名、不可编辑、不可归档、不可删除，不进入人员管理列表。
- 常驻矩阵第一行（转置后为第一列），行头显示未指派任务数；为 0 时压缩为窄行但不可隐藏，以便继续作为拖放目标。
- 行内按项目列展示未指派任务，渲染规则与其他格子完全一致。
- 从该行拖到任意人员格即完成指派；从其他行拖回该行即取消指派，均支持 5 秒撤销。
- 新建任务时人员留空即落到这里；从格子内新建默认带入人员，不会进入该行。
- 验收：对「待分配」发起改名、归档、删除均被拒绝；未指派任务只出现在该行，不出现在其他人员行。

### FR-11 单账号登录

- 一个账号，用户名 + 密码登录；前端先对「用户名 + 密码」做一次 SHA-256，库里只存这个摘要的 bcrypt 哈希。
- 无注册入口；账号在部署时由环境变量初始化，之后用户名不可改，密码可在设置页修改。
- 登录成功签发服务端签名 token（有效期 7 天），存 `localStorage`，请求带 `Authorization: Bearer`。
- 未登录访问任何页面跳转登录页；token 失效同样回登录页；支持退出登录。
- 不做过错次数限制：输错只提示，不锁定账号。
- 验收：错误密码有明确提示；token 过期后自动回登录页。

## 8. 业务规则汇总

| 编号 | 规则 |
|---|---|
| R1 | 任务必须属于一个项目和一个人员；「待分配」为系统人员，挂在其名下即未指派 |
| R2 | 人员姓名、项目名称均需唯一（去除首尾空格后比较） |
| R3 | 开始日、截止日均可为空；两者都有时开始日 ≤ 截止日；不做时区换算 |
| R4 | 有未完成任务的人员／项目不可归档 |
| R5 | 人员／项目名下存在任何任务时不可删除；删除项目还需输入名称确认 |
| R6 | 矩阵顺序由 `sort_order` 决定，可拖拽调整；新建条目追加末尾 |
| R7 | 格子内排序：有开始日的按开始日升序，日期不全的排在其后；同序按创建时间；已完成始终置底 |
| R8 | 日期筛选按「区间有交集」判断，不按完全包含 |
| R9 | 转置、筛选、弹窗状态均为纯前端状态，不写库 |
| R10 | 所有写操作即时生效，不做「保存」按钮式工作副本 |
| R11 | 系统人员「待分配」不可改名、不可归档、不可删除，固定排在第一位 |
